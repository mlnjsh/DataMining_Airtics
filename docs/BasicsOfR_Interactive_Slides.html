Setup

What is R?

A simple definition

R is a free language for working with data: calculating, analysing, and drawing charts. You type instructions, R answers immediately.

A tiny bit of history

  • Created in the 1990s by Ross Ihaka and Robert Gentleman in New Zealand (both names start with R!)
  • Free and open source — anyone can use it, forever, at no cost
  • Today: one of the world's most used tools for statistics and data mining

Why do WE learn it?

  • Built for data. Statistics, tables and charts are not add-ons — they are the whole point of R.
  • Free. No licence fees, unlike SPSS, SAS or Stata.
  • Thousands of packages. Ready-made tools for almost any analysis (we meet them in Part F).
  • Huge community. Nearly every beginner question is already answered online.
Talking to R feels like a conversation: you type 2 + 3, R replies 5. You ask again, it answers again. That is really all programming is here.

What is RStudio?

A simple definition

RStudio is a comfortable workspace built around R. R still does all the thinking — RStudio just makes working with R much easier.

What it adds on top of plain R

  • A place to write and save your code files
  • A window showing every variable you have created
  • Your plots, files, packages and help — all in one place
  • Little comforts: auto-complete, colours, keyboard shortcuts

An analogy

R is the engine. RStudio is the car built around it.

The engine does the actual work — but you would rather sit in a car with a steering wheel, mirrors and a dashboard than sit on a bare engine.

RStudio is made by a company called Posit (its old name was RStudio too). The free desktop version is all we need.

Important: RStudio does not work without R — the car cannot drive without its engine. That is why we install both, and why we install R first.

Point R at your folder: the working directory

The working directory is simply the folder R is currently looking at. When you save or load files, R looks there first. So we tell R: "work in my new folder."

Way 1 — with code: setwd()

# set working directory (edit path to yours)
setwd("C:/Users/You/Desktop/R_Practice")

set + wd = "set working directory". Again: forward slashes!

Way 2 — with menus (no typing)

In RStudio: Session → Set Working Directory → Choose Directory… then pick your folder.

Watch the console — RStudio types the matching setwd(...) command for you. Copy it into your script so tomorrow it is one keypress.

Most common beginner error in R: cannot open file 'data.csv' — nine times out of ten it just means the working directory is not where the file is. Now you know the fix.

Logarithms: log() asks "which power?"

A logarithm answers one question: "To what power must I raise the base to get this number?" log₁₀(1000) = 3 because 10³ = 1000.

# Careful: plain log() uses base e (natural log)
log(100)
# Example 1: base-10 log, two ways
log(100, base = 10)
log10(1000)
# Example 2: base-2 log (used in computing)
log2(8)
> log(100)
[1] 4.60517
> log(100, base = 10)
[1] 2
> log10(1000)
[1] 3
> log2(8)
[1] 3

Interpretation, in words

  • log10(1000) = 3 → "10 must be raised to the power 3 to reach 1000"
  • log2(8) = 3 → "2 × 2 × 2 = 8, so the answer is 3"
  • log(100) = 4.6 → "e must be raised to ~4.6 to reach 100"
Why data people love logs: they tame huge ranges. Incomes from ₹10,000 to ₹10 crore squash onto a neat scale of 4 to 8 — patterns hidden by a few giants become visible.

R follows BODMAS — brackets first

R computes exactly like your school maths teacher: Brackets → pOwers → Division/Multiplication → Addition/Subtraction.

# Same numbers, different answers!
5 + 3 * 2      # multiplication first
(5 + 3) * 2    # brackets first
> 5 + 3 * 2
[1] 11
> (5 + 3) * 2
[1] 16

The classic average trap

# average of 10, 20, 30 — WRONG:
10 + 20 + 30 / 3    # = 10+20+10 = 40 ✗
# RIGHT — brackets force the sum first:
(10 + 20 + 30) / 3  # = 60/3 = 20 ✓
Advice: when in doubt, add brackets. Extra brackets never hurt — ((2+3))*4 is ugly but correct. Missing brackets silently give wrong answers.

Variables

Variables: boxes with labels

A variable is a labelled box in R's memory. You put a value in, give the box a name, and from then on the name stands for the value.

# The arrow <- puts the value INTO the name
x <- 10        # box "x" now holds 10
y <- 3         # box "y" now holds 3
x + y          # use the names like numbers
# A realistic pair:
price <- 250   # ticket price
qty   <- 4     # number of tickets
price * qty    # total bill
> x + y
[1] 13
> price * qty
[1] 1000

Variables

What may a variable be called?

The rules (R enforces these)

  • Use letters, digits, dot and underscore: sales_2024, total.marks
  • Must start with a letter — 2sales is an error
  • No spaces — my sales is an error; write my_sales
  • R is case-sensitive: Sales, sales and SALES are three different boxes!

The good habits (humans thank you)

  • Describe the content: monthly_revenue beats mr beats x
  • Pick one style and stick to it — snake_case is the most common in modern R
  • Avoid names R already uses: mean, sum, c, T, pi — it works, but causes confusing bugs later
Case-sensitivity is the #1 beginner trap: you create Sales <- 100, later type sales, and R says object 'sales' not found. The box exists — under a capital S.
Variables

What is overwriting?

A box can hold only one value. Assign again to the same name and the new value replaces the old one — silently, with no warning. That replacement is called overwriting.

# Example 1: plain replacement
x <- 10       # x is 10
x <- 99       # x is now 99; the 10 is gone forever
x
# Example 2: updating using the OLD value
score <- 50
score <- score + 25   # right side computed first: 75
score
> x
[1] 99
> score
[1] 75

How R reads score <- score + 25

  1. Right side first: fetch score's current value (50), add 25 → 75
  2. Then assign: put 75 into the box called score

This "update in place" pattern is everywhere in real code — running totals, counters, cleaning data step by step.

Two-sided coin: overwriting is how you update things on purpose — and how you destroy things by accident. R never asks "are you sure?". Choose distinct names when you want to keep both values.

Comments: notes R ignores, humans need

Everything after a # on a line is invisible to R. Comments exist for one reader only: a human — usually future-you, three weeks from now.

# Example 1: a comment on its own line
# Calculate total bill for 4 tickets
price <- 250
total <- price * 4

# Example 2: a comment at the end of a line
total * 0.9   # apply 10% discount
> total * 0.9
[1] 900

# the comments produced no output at all -
# R never even read them

What makes a GOOD comment?

  • Say WHY, not what: # apply festival discount ✓  vs  # multiply by 0.9 ✗ (the code already says that)
  • Comment every block in your scripts — like section headings in an essay
  • Use comments to switch lines off while testing: put # in front, the line "sleeps"
Course rule: from here on, every script we write is commented — including the sales case study and the final case study. Copy the habit; it is the cheapest professional skill there is.

The vector — R's most important idea

A simple definition

A vector is an ordered row of values of the same type stored under one name. Think of a strip of connected boxes instead of a single box.

Why vectors rule R

  • A week of sales = 7 numbers → one vector, not 7 variables
  • Commands work on all values at once — no loops needed
  • Every column of every dataset you will ever load is a vector

Vectors

Slicing by condition — the data mining move

Instead of positions you can put a question in the brackets. R keeps the elements that answer TRUE. This is filtering — the single most-used move in data analysis.

v <- c(2, 4, 6, 8, 10)
# Step 1: the question alone gives logicals
v > 5
# Step 2: the question INSIDE brackets filters
v[v > 5]
# which() tells you the POSITIONS instead
which(v > 5)
> v > 5
[1] FALSE FALSE  TRUE  TRUE  TRUE
> v[v > 5]
[1]  6  8 10
> which(v > 5)
[1] 3 4 5

How R thinks, step by step

  1. v > 5 asks all five elements at once → F F T T T
  2. v[F F T T T] keeps only the TRUE positions → 6, 8, 10

The brackets take a logical vector just as happily as positions. TRUE = keep, FALSE = drop.

Translate to business: "show me days with sales above 5" — that sentence IS v[v > 5]. Every filter you will ever run — high-value customers, failed transactions, outliers — is this one idea.

NA is contagious — and the antidote

z <- c(2, 3, NA, 4)

mean(z)

# Antidote: na.rm = TRUE ("remove NAs first")

> mean(z)
[1] NA
> sum(z)
[1] NA
> mean(z, na.rm = TRUE)
[1] 3
> sum(z, na.rm = TRUE)
[1] 9

Why does R answer NA at first?

R is being honest: "one value is unknown, so the true total is unknown." You must explicitly say "ignore the missing ones" with na.rm = TRUE.

Counting the damage

sum(is.na(z))   # how many missing? -> 1

The TRUE=1 trick from Part D! is.na() gives TRUEs where values are missing; sum() counts them.

Professional habit: the FIRST question to ask any new dataset is "how much is missing?" — sum(is.na(x)) answers it in one line.

A broken vector: what does c(2, 3, , 4) do?

A typo every beginner makes eventually: two commas with nothing between them. Let us print it and see how R reacts.

v
> v <- c(2, 3, , 4)
Error in c(2, 3, , 4) : argument 3 is empty
> v
Error: object 'v' not found
Read the message like a detective: "argument 3 is empty" — the 3rd slot between commas holds nothing. And note: because the command failed, v was never created — that is the second error.

The lesson

  • An empty slot is an error, not a missing value
  • Missing data must be written explicitly as NA
  • Errors are not failures — they are R protecting you from silent nonsense. Read them; they usually say exactly what is wrong.

Statistics

Why statistics before data mining?

Data mining stands on a handful of statistical ideas. Master these five and half the field's vocabulary unlocks. Each answers one plain question about a pile of numbers.

1 Mean

"What is the typical value?" — the balancing point

2 Median

"What is the middle value?" — immune to extremes

3 Mode

"What is the most common value?"

4 Variance

"How spread out are the values?" (squared units)

5 Std. deviation

"Spread, in the same units as the data" — √variance

Coming up

Each gets its own slide: formula → 2 examples → plain-language interpretation → then all five on our sales data.

The two families: mean/median/mode describe the centre ("where do values sit?"); variance/sd describe the spread ("how far do they wander?"). A full picture of data needs one of each.
Statistics

The mean — add up, divide by count

The formula, in words

mean = (sum of all values) ÷ (how many values)

In symbols: x̄ = Σx / n — "x-bar equals sum of x over n". Same thing.

# Example 1: five simple numbers
mean(c(2, 4, 6, 8, 10))
# Example 2: eight students' marks
marks <- c(45, 67, 89, 72, 55, 91, 67, 60)
mean(marks)
> mean(c(2, 4, 6, 8, 10))
[1] 6
> mean(marks)
[1] 68.25

Interpretation, in simple language

"The class average is 68.25" = if every student had scored identically, they would each have 68.25. It is the balancing point of the data — a see-saw with all values as weights balances exactly at the mean.

The mean's weakness (remember this): it listens to EVERY value, so one extreme value can drag it far from "typical". The next slide has the cure.
Statistics

The median — line them up, take the middle

The recipe

  1. Sort the values small → large
  2. Odd count: the middle one is the median
  3. Even count: average the middle two
# Example 1: odd count - middle value
median(c(3, 1, 9, 5, 7))   # sorted: 1 3 5 7 9
# Example 2: even count - average of middle two
median(c(2, 4, 6, 8))      # (4+6)/2
> median(c(3, 1, 9, 5, 7))
[1] 5
> median(c(2, 4, 6, 8))
[1] 5

Interpretation, in simple language

"The median is 5" = half the values sit below 5, half above. The median only cares about the middle position — extremes at the ends cannot move it.

That immunity to extremes is the median's superpower. The next slide shows it saving us from a very misleading average.
Statistics

Mean vs median: the salary story

Five friends in a café. Four earn modest salaries; one is a startup founder. Watch what each measure reports.

# salaries (Rs/month): 4 friends + 1 founder
salary <- c(30000, 35000, 32000,
            38000, 1000000)
mean(salary)
median(salary)
> mean(salary)
[1] 227000
> median(salary)
[1] 35000

Which number tells the truth?

Mean = ₹2,27,000 — yet NOBODY in the café earns close to that. The founder dragged the balancing point far to the right.

Median = ₹35,000 — an honest "typical friend". The founder is just "one person above the middle", however rich.

Rule of thumb: data with big outliers or long tails (salaries, house prices, hospital bills) → report the median. Symmetric, well-behaved data → mean is fine (and mathematically convenient). News headlines about "average income" — now you know what to ask.

Interpretation, in simple language

Statistics

Variance — how far do values wander?

The idea, step by step

  1. Find the mean
  2. Measure each value's distance from the mean
  3. Square the distances (so minus signs cannot cancel plus signs)
  4. Average the squares* — that is the variance

*R divides by n−1 rather than n — a small statistical correction for samples. The idea is unchanged.

# Example 1: tight data - tiny variance
var(c(49, 50, 51))
# Example 2: spread data - big variance,
# SAME mean of 50!
var(c(20, 50, 80))
> var(c(49, 50, 51))
[1] 1
> var(c(20, 50, 80))
[1] 900
Same centre, wildly different spread — this is exactly what the mean alone cannot see, and why spread measures exist. One catch: 900 is in squared units (rupees², marks²) — awkward to interpret. The fix is next.
Statistics

Standard deviation — spread you can talk about

sd = √variance. Taking the square root brings the spread back into the same units as the data — rupees, marks, kilograms — so humans can discuss it.

# Two shops, SAME mean daily sales (50000):
shopA <- c(48000, 52000, 50000, 49000, 51000)
shopB <- c(20000, 90000, 30000, 80000, 30000)
mean(shopA); mean(shopB)
sd(shopA)
sd(shopB)
> mean(shopA); mean(shopB)
[1] 50000
[1] 50000
> sd(shopA)
[1] 1581.139
> sd(shopB)
[1] 32403.7

Interpretation, in simple language

Shop A: sd ≈ ₹1,581 — "a typical day misses the average by about ₹1,500." Steady, predictable, easy to plan staff and stock for.

Shop B: sd ≈ ₹32,404 — "a typical day misses by ₹32,000!" A rollercoaster: same average income, completely different business.

The takeaway of Part G: never report an average without its spread. "Mean 50,000, sd 1,600" and "mean 50,000, sd 32,000" are different worlds hiding behind the same mean. Also: sd(x)^2 = var(x) — check it!

1. House prices in a city include a few ultra-luxury mansions. Which "typical price" is more honest?

Right: mansions drag the mean up just like the founder's salary did; the median stays at the honest middle. Variance measures spread, not "typical".

Data frames

The data frame — R's table

A simple definition

A data frame is a table: rows are things (customers, days, cars), columns are facts about them (name, sales, price). Like one sheet in Excel — living inside R.

The key insight

Each column IS a vector (one type per column: numbers, text…). A data frame is simply several equal-length vectors standing side by side. Everything you learned in Part E applies, column by column.

You have already met two!

  • mtcars — 32 rows (cars) × 11 columns (specs)
  • npk — 24 rows (plots) × 5 columns (fertilisers, yield)

And every CSV or Excel file you will ever load into R arrives as a data frame. It is the standard shape of data in data mining.

This part's plan: build one from scratch → measure it → name its columns → add a column → slice it → filter it. Our example: a small shop's six months.
Data frames

Defining a data frame

shop <- data.frame(
  month = c("Jan","Feb","Mar",
            "Apr","May","Jun"),
  units = c(120, 150, 180, 90, 210, 160),
  price = c(250, 250, 260, 260, 270, 270)

Slicing the table: [row, column]

One bracket, two slots: shop[row, column]. Leave a slot empty to say "all of them".

One row (all columns)

2   Feb   150   250   37500

One column (all rows)

Memory hook: "RC" — Row comma Column, in that order, like naming a cell in battleship. shop[2, ] = "row 2, everything". shop[, "units"] = "every row, column units". All the vector slicing tricks (ranges, minus, names) work in both slots.
Data frames

Filtering rows — conditions in the row slot

# Example 1: months earning above 40000
shop[shop$revenue > 40000, ]
# Example 2: just one month's full row
shop[shop$month == "May", ]
> shop[shop$revenue > 40000, ]
  month units price revenue
3   Mar   180   260   46800

Same filtering idea as vectors

The condition shop$revenue > 40000 produces TRUE/FALSE for each of the 6 rows; putting it in the row slot keeps the TRUE rows. The comma then says "…and all columns".

You now hold the master key of data mining: "show me the rows where ___" — high-revenue months, churned customers, fraudulent claims. It is this one line, with a different condition.

Loops

What is a loop?

A simple definition

A loop tells R: "repeat this block of code again and again" — once per item, or until a condition says stop. You write the instruction once; R does the repetition.

Why loops matter

  • Print a message for each of 500 customers — without writing 500 lines
  • Keep doubling an investment until it crosses a target
  • Process every file in a folder, one by one

The road map for this part

ToolRepeats…
foronce for each item in a collection
whileas long as a condition stays TRUE
repeatforever — until you break out
break / nextcontrol: stop the loop / skip one round
alternativesthe R way: often no loop at all!
Honest R advice up front: because vectors already work "all at once" (v * 2!), R needs loops less than other languages. We learn them because they are essential thinking tools — and then learn when to skip them.
Loops

The for loop — "once for each item"

Read it aloud: "for each value i in this collection, run the code in the curly brackets { }."

1 · Count 1 to 5

# i takes each value in 1:5,
# one round per value
for (i in 1:5) {
  print(i)
}
[1] 1
[1] 2
[1] 3
[1] 4
[1] 5

2 · Loop over words

# works on ANY vector,

for (f in c("apple",

}

[1] "I like banana"
[1] "I like mango"

for (s in c(4200, 5100, 3800)) {

The while loop — "as long as this is TRUE"

Use while when you do not know how many rounds you need — only the condition for continuing. R checks the condition before every round.

1 · Count to 5, by hand

i <- 1
while (i <= 5) {
  print(i)
  i <- i + 1   # step forward!
}
[1] 1
[1] 2
[1] 3
[1] 4
[1] 5

2 · Double money until ₹1000

money <- 100
years <- 0
while (money < 1000) {
  money <- money * 2
  years <- years + 1
}
print(money)
print(years)
[1] 1600
[1] 4

3 · A countdown

n <- 3
while (n > 0) {
  print(n)
  n <- n - 1
}
print("Go!")
[1] 3
[1] 2
[1] 1
[1] "Go!"
The classic while-loop bug: forget the step line (i <- i + 1) and the condition stays TRUE forever — an infinite loop. R appears frozen. The rescue: press the Stop sign in the console (or Esc). Example 2's answer in words: ₹100 doubling yearly needs 4 years to pass ₹1000 (it reaches 1600).
Loops

The repeat loop — "loop forever, until break"

repeat has NO condition of its own — it loops endlessly. YOU must provide the exit: an if (...) break inside. Check-at-the-end thinking.

1 · Count to 3

i <- 1
repeat {
  print(i)
  i <- i + 1
  if (i > 3) break  # exit!
}
[1] 1
[1] 2
[1] 3

2 · Double until above 50

x <- 5
repeat {
  x <- x * 2
  if (x > 50) break
}
print(x)
[1] 80

3 · Days until ₹10,000

sales <- c(4200, 5100,
           3800, 4600)
total <- 0; day <- 0
repeat {
  day   <- day + 1
  total <- total + sales[day]
  if (total > 10000) break
}
print(day)
print(total)
[1] 3
[1] 13100
When would you pick repeat? When the exit test belongs at the end of the round — "do it at least once, then decide". Example 3 in words: the shop crosses ₹10,000 of cumulative sales on day 3. In practice for and while cover most needs; recognise repeat when you meet it.
Loops

Loop control: break and next

Two steering commands that work inside any loop: break = "stop the whole loop now" · next = "skip the rest of THIS round, continue with the next one".

1 · break: stop at 4

for (i in 1:10) {
  if (i == 4) break
  print(i)
}
# rounds 4..10 never happen
[1] 1
[1] 2
[1] 3

2 · next: evens only

for (i in 1:6) {
  # odd? skip this round
  if (i %% 2 != 0) next
  print(i)
}
[1] 2
[1] 4
[1] 6

3 · next: skip missing data

for (s in c(4200, NA, 3800)) {
  if (is.na(s)) next
  print(s)
}
# the NA day is passed over
[1] 4200
[1] 3800
Memory hook: break breaks OUT of the loop entirely (we used it to escape repeat); next jumps to the NEXT round. Example 2 reuses %% from Part B — odd numbers leave remainder 1, so they get skipped. Old R books may say "continue" — in R it is next.

Loop alternatives — often R needs no loop

R's superpower is vectorization: whole-vector operations that replace loops — shorter to write, faster to run, harder to get wrong.

1 · Arithmetic: just do it

  print(v[i] * 2)

# the R way - one line:

> v * 2
[1]  4  8 12 16 20

2 · Totals: sum(), not a loop

# the accumulator loop
# from slide 90... or:
sum(c(4200, 5100, 3800))

> sum(c(4200, 5100, 3800))

Functions

What is a function?

A simple definition

A function is a named recipe: it takes ingredients (arguments), follows its steps (body), and hands back a dish (return value). Write it once — use it a thousand times.

You have used functions all day!

sqrt(144), mean(marks), paste("a","b") — every name(input) since Part B was someone's function. Today you move from user to author.

The anatomy — one shape to learn

square <- function(x) {
  x^2
}
  • square — the name (a variable, assigned like any other!)
  • function(x) — the argument list: what it needs to be given
  • { x^2 } — the body: the steps
  • The body's last value is returned automatically (writing return(x^2) is allowed but optional)
Why bother? Repeating the same 5 lines for every dataset invites copy-paste errors. Wrap the lines in a function and there is exactly ONE place to write them — and one place to fix them. Five examples coming, easiest first.
Functions

Examples 1 & 2 — one argument in, one value out

Example 1 · square a number

> square(6)
[1] 36

bill_total <- function(amount,
                       discount = 0.10) {
  amount * (1 - discount)
}
bill_total(1000)        # default 10%
bill_total(1000, 0.25)  # festival 25%
> bill_total(1000)
[1] 900
> bill_total(1000, 0.25)
[1] 750
Now the whole course makes more sense: mean(z, na.rm = TRUE), round(x, 2), seq(0, 20, by = 5) — named arguments and defaults were there all along. na.rm defaults to FALSE; that is exactly why you must say TRUE yourself.
Functions

Example 5 — your own analysis tool

Functions can hold several steps. This one prints a three-line sales report for ANY vector you feed it — Part G, bottled.

# a reusable mini-report
sales_report <- function(x) {
  cat("Total  :", sum(x, na.rm = TRUE), "\n")
  cat("Average:", round(mean(x, na.rm = TRUE), 1), "\n")
  cat("Best   :", max(x, na.rm = TRUE), "\n")
}
# feed it our week of sales
week <- c(12000, 15500, 9800, 14200,
          21000, 25500, 8700)
sales_report(week)
> sales_report(week)
Total  : 106700 
Average: 15242.9 
Best   : 25500

Why this one is special

  • Several steps, one name. Three cat() lines run every call
  • Built from other functions — sum, mean, max, round: functions calling functions is how all real programs grow
  • Reusable instantly: sales_report(next_week), sales_report(products$revenue) — any numbers, same report
  • NA-safe by design — na.rm = TRUE is baked in once, never forgotten again
You are now an author: five functions written — square, greet, rect_area, bill_total, sales_report. Every package from Part F is just someone's folder of functions like these, polished and shared.
Quick check

Part J — functions quiz

1. Given double <- function(x) { x * 2 }, what does double(7) return?

Right: R returns the body's last value on its own; return() is optional. (print is only needed to SHOW things inside loops — returning is different from printing.)

2. f <- function(a, b = 5) { a + b }. What is f(10)?

Right: unspecified arguments take their defaults, so a=10, b=5 → 15. Only arguments WITHOUT defaults (like a) are required.

Histogram — the shape of one variable

# 200 customer bill amounts (Rs)

How to read it

Each bar = a range of bill sizes; height = how many bills landed there. The shape is a hill centred near ₹500 — most customers spend ₹400–600, very few below ₹200 or above ₹800. Symmetric hill → mean ≈ median, no worrying outliers.

Scatter plot — two variables, one dot each

# from our shop data frame:
# does selling more units mean more revenue?
plot(shop$units, shop$revenue,
  pch  = 19,              # solid dots
  col  = "#276DC3",
  main = "Units Sold vs Revenue",
  xlab = "Units sold",
  ylab = "Revenue (Rs)")

How to read it

Each dot = one month: across = units, up = revenue. The dots climb from bottom-left to top-right — more units, more revenue, an upward (positive) relationship. Dots that buck a trend are the interesting ones: a high-units low-revenue month would beg "was there a discount?"

Box plot — comparing distributions

# 8 weekday vs 8 weekend daily sales
boxplot(list(Weekday = weekday,
             Weekend = weekend),
  col  = c("#276DC3", "#F07818"),
  main = "Sales: Weekday vs Weekend",
  ylab = "Sales (Rs)")

How to read one box

The thick line = median. The box = the middle half of days (1st to 3rd quartile — summary()'s quartiles, drawn!). The whiskers = the usual range; lone dots beyond them would be outliers.

The comparison: the weekend box floats entirely above the weekday box — even a weak weekend beats a good weekday. Two summary()s, one picture.

Final project

From console to script file (.R)

Console commands vanish when you close RStudio. A script is a saved text file of R commands — your analysis, repeatable forever. Time to write yours.

Create, write, save

  1. File → New File → R Script (or Ctrl+Shift+N) — a blank page opens in the Source pane
  2. Type commands one per line, comments above each block
  3. Save (Ctrl+S) into your working folder as my_analysis.R — the .R ending marks it as an R script

Run it — three ways

  • One line: cursor on it → Ctrl+Enter — runs in the console, cursor moves down. The rhythm of R work!
  • A selection: highlight lines → Ctrl+Enter
  • The whole file: the Source button — or source("my_analysis.R")
